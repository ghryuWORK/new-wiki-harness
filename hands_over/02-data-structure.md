# 2. Raw 회의록 최소 Schema

## 메타데이터 (YAML Front Matter)

```yaml
---
출처: Notion | 직접기록 | 기타
notion_url: "https://..."  # Notion 문서 링크 (필요시)
회의일: 2026-08-10
가져온시점: 2026-08-10  # 또는 최초 작성일
참석: 이지혜(PM), 박준서(개발), 최민아(디자인)  # 이름(역할) 형식
---
```

### 메타데이터 필드 설명

| 필드 | 필수 | 형식 | 예시 |
|------|------|------|------|
| `출처` | ✅ | 텍스트 | Notion, 직접기록 |
| `회의일` | ✅ | YYYY-MM-DD | 2026-08-10 |
| `가져온시점` | ✅ | YYYY-MM-DD | 2026-08-08 |
| `참석` | ✅ | 이름(역할), ... | 이지혜(PM), 박준서(개발) |
| `notion_url` | ❌ | URL | https://notion.so/... |

## 본문 구조 (자유 형식)

### 필수 섹션

**1) 안건 (## 안건)**
```markdown
## 안건
1. 주제 1
2. 주제 2
3. 주제 3
```

**2) 회의 내용**
- 각 주제별 자유로운 기록
- 사람 이름으로 발언 표시: `- 이름: 내용`
- 논의 결과/결정사항 명시

**3) 액션 아이템 (## 액션 아이템)**
```markdown
## 액션 아이템
- [ ] 이름 — 할일 설명 (~마감일)
- [x] 이름 — 완료된 항목
  - 상세 내용 (선택)
```

### 선택 섹션

**기타 (## 기타)**
- 특이사항, 후속 회의 예정, 보류 사항 등

## 구조화를 위한 마킹

Raw 계층의 회의록은 **자유 형식 그대로 유지**하되, Wiki 계층으로 추출 시 아래 마크를 활용:

### 결정사항 명시 방식
```markdown
### 결정
- **내용** | Owner: 이름 | Due: 2026-08-15
```

### 보류/질문 명시 방식
```markdown
### 보류
- **내용** | Status: pending | Owner: 이름

### 질문
- **내용** | Owner: 이름
```

**중요**: 원본 회의록은 이러한 구조를 **강제하지 않음**
- 원본에서 의도가 명확하면 자유 형식 유지
- Wiki 추출 시에만 구조화

## 파일 이름 규칙

```
YYYY-MM-DD-{회의명}.md
예: 2026-04-16-제품주간회의.md
    2026-06-25-온보딩개선회의.md
    2026-07-09-정산주기논의.md
```

## 최소 필수 요소 체크리스트

- ✅ 메타데이터 4개 필드 (출처, 회의일, 가져온시점, 참석)
- ✅ 회의 제목 (# YYYY-MM-DD 회의명)
- ✅ 안건 섹션 (## 안건)
- ✅ 회의 내용 (자유 형식)
- ✅ 액션 아이템 (## 액션 아이템)
