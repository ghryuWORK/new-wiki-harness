## 🎓 핵심 학습

### 1. Raw = Truth 원칙의 중요성
```
처음: "Raw를 완벽하게 하려고" → 실패
지금: "Raw는 있는 그대로, Wiki에서 보충" → 성공
```

### 2. 문제는 숨기는 게 아니라 명시하는 게 개선
```
A-002 미추적 → untracked 상태로 명시
P-001 미정 → owner: unassigned로 명시
→ 이를 통해 다음 회의에서 즉시 조치 가능
```

### 3. Follow-up 체계의 필수성
```
없음: A-002는 4주 미보고 상태 지속
있음: 매 회의마다 "이전 회의 액션 추적" 섹션
→ 미완료 항목이 회의에서 명시적으로 다뤄짐
```

### 4. Status 값의 정확성
```
pending vs pending_implementation vs in_progress
→ 이 구분이 정확하면 상황 파악이 명확해짐
```

### 5. 리소스 충돌의 사전 예방
```
A-004 vs A-005 동시 진행 불가
→ 우선순위 명시 + 복귀 시점 정의
→ 앞으로는 리소스 먼저 확인
```
