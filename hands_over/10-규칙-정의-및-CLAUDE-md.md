## 📖 핵심 규칙 요약

### 핵심 원칙 (3가지)

```
Raw = SSOT (원본, 순수 유지)
    ↓
Schema = 변환 규칙 (Raw → Wiki)
    ↓
Wiki = 파생물 (재생성 가능)
```

### 해야 할 규칙 (DO) - 6가지 분류

#### Raw 회의록 기록 (R-1~4)
✅ 있는 그대로 기록  
✅ 필수 메타데이터 포함 (출처, 회의일, 가져온시점, 참석)  
✅ 필수 섹션 포함 (안건, 회의 내용, 액션 아이템)  
✅ 발언자를 명확하게 (`- 이름: 내용`)

#### Wiki 항목 관리 (W-1~6)
✅ 매 회의마다 항목 생성 (D/A/P)  
✅ 항상 ID 부여 (D-001, A-001, P-001)  
✅ Source 명시 (Raw 출처 기록)  
✅ Status를 현재 상태로 유지  
✅ 모든 문제점을 명시 (미추적, 블로킹, 위험)  
✅ 연관 항목 링크 (선행조건, 의존성)

#### 의사결정 프로세스 (D-1~3)
✅ 선행 조건 확인 후 결정  
✅ 의사결정 근거 명시  
✅ 우선순위 변경은 명시적으로

#### 액션 아이템 관리 (A-1~4)
✅ 담당자 필수, 기한 필수  
✅ 기한 경과 시 즉시 기록  
✅ 블로킹된 액션 명시 (무엇이 블로킹하는가)  
✅ 매주 상태 업데이트

#### Follow-up 추적 (F-1~3)
✅ "이전 회의 액션 상태 확인" 프로세스 (매 회의마다)  
✅ 보류 사항 재논의  
✅ 미추적 항목 조치

#### 우선순위 결정 (P-1~2)
✅ 우선순위는 의사결정  
✅ "기간 불명확" 금지 (언제까지인지 명시)

### 하지 말아야 할 규칙 (DON'T) - 5가지 분류

#### Raw 회의록 관련 (R-DO-1~3)
❌ Raw를 "개선"하려 하지 말기  
❌ Raw를 사후 수정하지 말기 (4시간 이상 경과 후)  
❌ Raw의 구조를 변경하지 말기

#### Wiki 관련 (W-DO-1~5)
❌ 미추적 항목을 방치하지 말기  
❌ "기타"에만 기록하지 말기 (액션/보류로 명시하기)  
❌ ID 재사용하지 말기  
❌ Owner 없이 액션 생성하지 말기  
❌ 기한 없이 액션 생성하지 말기

#### 의사결정 관련 (D-DO-1~3)
❌ 선행 조건 무시하고 결정하지 말기  
❌ 근거 없이 결정하지 말기  
❌ 우선순위 변경을 암묵적으로 하지 말기

#### Follow-up 관련 (F-DO-1~3)
❌ 미해결 항목을 "닫기" 금지  
❌ "다음에 확인하자" 후 안 하지 말기  
❌ 상태 업데이트 안 하지 말기

#### 리소스 관리 관련 (RS-DO-1~2)
❌ 리소스 충돌을 무시하지 말기  
❌ "다른 사람이 할 것"을 기대하지 말기 (담당자/기한 명시)

## 📋 체크리스트

### 회의 진행 시

#### 회의 전
- [ ] Raw 회의록 파일명 준비 (YYYY-MM-DD-회의명.md)
- [ ] 이전 회의의 A/P 상태 확인 (미완료 항목 리스트 작성)
- [ ] Wiki 폴더 정리

#### 회의 중
- [ ] 발언자를 명확하게 기록
- [ ] 각 주제별로 "결정/액션/미해결" 판단
- [ ] 우선순위 변경 시 근거 기록
- [ ] 미정 항목에는 담당자, 기한 정하기

#### 회의 후
- [ ] Raw 회의록 작성 완료
- [ ] 각 D/A/P에 ID 부여
- [ ] Wiki 파일 생성
- [ ] 기존 항목 상태 업데이트
- [ ] 연관 항목 링크 추가
- [ ] "미추적", "블로킹", "위험" 항목 표시
- [ ] 팀에 새로운 항목 공지

#### 주간
- [ ] 진행 중인 A 상태 확인
- [ ] Red flag (기한 임박, at_risk) 점검
- [ ] 블로킹 원인 해결 검토

#### 월간
- [ ] 완료된 항목 review
- [ ] P (pending)가 너무 많으면 의사결정 구조 점검
- [ ] "untracked" 항목이 있으면 추적 시작

## 🔍 발견된 문제점과 규칙화

### 문제 1: A-002 미추적
**원인**: Follow-up 추적 체계 부재  
**규칙**: F-1 (이전 회의 액션 상태 확인 프로세스)  
**구현**: 매 회의 시작 시 "지난 회의 액션 추적" 섹션 필수

### 문제 2: P-001 미실행
**원인**: "기타"에만 기록, 담당자/기한 미정  
**규칙**: W-DO-2 (기타에만 기록 금지)  
**구현**: P-xxx 생성 + 담당자/기한 즉시 설정 필수

### 문제 3: A-004 블로킹
**원인**: 리소스 충돌 사전 예측 안 됨  
**규칙**: RS-DO-1 (리소스 충돌 무시 금지)  
**구현**: 의사결정 전 리소스 확인 + 복귀 시점 명시

### 문제 4: D-003 연기
**원인**: 선행 조건(A-003) 미확인 상태에서 결정  
**규칙**: D-1 (선행 조건 확인 후 결정)  
**구현**: 선행 조건 명시 + 주기적 진행 상황 확인

### 문제 5: 우선순위 변경 미명시
**원인**: 우선순위 결정이 명시적이지 않음  
**규칙**: P-1 (우선순위는 의사결정) + P-2 (기간 불명확 금지)  
**구현**: 모든 변경의 근거 + 복귀 시점 명기

## 📊 스키마 1.1 업데이트

### Decision Status 확대 (5 → 7개)
```
기존: open, closed, pending, unclear, at_risk
추가: pending_implementation, in_progress
```

### Action Status 확대 (5 → 7개)
```
기존: open, in_progress, completed, blocked, untracked
추가: on_hold, at_risk
```

### 필수 섹션 명확화

#### Decision
```
필수: 내용, 배경, 의사결정 세부, 현재 상태
다중 회의면 필수: 상태 변화
```

#### Action
```
필수: 액션 내용, 기한, 진행 상황, 영향도, 연관 항목
높은 우선순위면 필수: 모니터링 필요 여부
리소스 충돌 있으면 필수: 리소스/의존성
다중 회의면 필수: 상태 변화
```

#### Pending
```
필수: 문제 설명, 배경, 현재 상태, 영향도, 개선 필요
```
