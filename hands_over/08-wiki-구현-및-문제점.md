## 🚨 발견된 주요 문제점

### 1️⃣ A-002: 계약 조건 확인 (미추적)

**상황**
```
2026-04-16 회의
└─ A-002 할당: 강태우 (기한: 2026-04-30)
   └─ "PG사 계약 조건 확인, 특히 최소 거래액"

2026-05-14 회의 (4주 경과)
└─ A-002 언급: 0회 (완전히 사라짐)
   └─ 그동안의 진행 상황 불명
```

**문제점**
- A-002가 기한(4월 30일)을 경과했으나 보고 없음
- D-002 (PG사 A사 선정)은 A-002 결과를 기다려야 했음
- 계약 조건 미검토 상태에서 A사 선정됨

**영향도**
- D-002 (PG사 선정)의 전제 조건 미충족
- 최소 거래액 조건이 있으면 엔터프라이즈 계약에 영향
- 강태우가 2026-04-16에 지적했던 우려가 무시된 형태

**근본 원인**
- Follow-up 추적 체계 부재
- Raw 회의록에 "이전 회의 액션 추적" 섹션 없음

### 2️⃣ P-001: 정산 프로세스 확인 (미실행)

**상황**
```
2026-04-16 회의
└─ D-001 결정: 정산 주기 월 1회
└─ "기타"에 P-001 기록: 재무팀 정산 프로세스 확인 필요
   ├─ 담당자: 미정 ❌
   └─ 기한: 명시 없음 ❌

2026-05-14 회의 (4주 경과)
└─ P-001 언급: 0회
```

**문제점**
- "기타"에만 기록 → 추적 대상이 아님으로 취급
- 담당자, 기한 미정 → 실행 불가능한 상태
- D-001은 결정되었으나 구현 준비 부재

**영향도**
- D-001 (정산 주기 월 1회) 구현 불가
- 고객사 공식 공지 불가
- 정산 업무 프로세스 정의 지연

**근본 원인**
- 의사결정 후 구현 대책이 없음
- "기타"는 액션이나 명확한 보류 항목이 아님

### 3️⃣ A-004: Q3 대시보드 스펙 (우선순위 충돌)

**상황**
```
2026-04-16 회의
└─ A-004 할당: 최민아 (기한: 2026-05-07)
└─ 이지혜: "Q3에 반드시 [대시보드를] 넣겠다"

2026-05-14 회의
├─ A-004 상태: "잠시 홀드" (온보딩 분석 때문에)
└─ A-005 (온보딩 이탈률)이 우선순위를 차용
   └─ 최민아가 동시에 A-004와 A-005를 할 수 없음
```

**문제점**
- 원래 기한(2026-05-07) 경과
- "잠시 홀드"의 기간이 정해지지 않음
- 리소스 충돌 미해결

**영향도**
- Q3 계획 변동 (이지혜의 약속 vs 현재 블로킹)
- 우선순위 충돌 미명확

**근본 원인**
- 새 액션(A-005) 추가 시 기존 항목과의 영향도 분석 미흡
- 우선순위 결정의 명시성 부족

### 4️⃣ D-003: 결제 연동 일정 연기 (4주)

**상황**
```
2026-04-16 회의
└─ D-003: 5월 말 목표 설정
   └─ 선행 조건: PG사 선정 + 스펙 문서 확보

2026-05-14 회의
└─ D-003 변경: 6월 중순으로 연기 (4주)
   └─ 사유: A사 스펙 문서를 아직 못 받음
```

**문제점**
- A-003 (스펙 확보)이 현재 "3일째 회신 없음" 상태
- A-003 기한(2026-05-21)을 못 맞추면 D-003 달성 불가

**영향도**
- 엔터프라이즈 고객 3곳 계약 지연
- 4주 일정 지연

**근본 원인**
- 선행 조건을 확인하지 않고 PG사 선정 (D-002)
- A사 스펙 미수령 상태에서 선정

### 5️⃣ 우선순위 결정의 명시성 부족

**상황**
```
2026-04-16
└─ "온보딩 개선은 후순위로 미룸"
└─ "Q3에 반드시 [대시보드를] 넣겠다" (이지혜)

2026-05-14
└─ D-004: "로드맵상 후순위이나 데이터는 봐두자"
└─ 결과: A-005가 A-004를 블로킹
```

**문제점**
- 우선순위 변경의 근거 불명확
- CS 피드백은 지속적이었는데 왜 지금 분석하는가?
- 우선순위 결정 기준이 없음

## 📋 Wiki 구현으로 개선된 점

- 각 D/A/P에 ID 부여 (D-001, A-002 등)
- 상태(status) 명시로 한눈에 파악
- "미추적" "블로킹" 같은 상태를 Wiki에 기록

### 2. 문제점이 가시화됨
- A-002의 "untracked" 상태를 명시
- P-001의 "담당자 미정" 명시
- A-004의 "블로킹" 상태 명시

### 3. 연관 항목을 통해 의존도 명확
- D-003 ← A-003 (필수 선행)
- A-004 ← A-005 (리소스 충돌)
- D-002 ← A-002 (미충족 전제 조건)

### 4. 두 회의 간의 변화가 기록됨
- "상태 변화" 섹션으로 2026-04-16 → 2026-05-14 추적
- "미해결" "우선순위 변경" 같은 키워드로 검색 가능

## 🎓 학습한 점 (Raw vs Wiki 설계)

### Raw는 순수 원본
- 회의에서 일어난 일을 있는 그대로 기록
- 추적 부실, 미정 사항도 그대로 기록되는 게 정상
- Raw를 "개선"하려 하면 안 됨

### Wiki는 파생 계층
- Raw의 부족한 부분을 보충
- 미추적 항목을 "untracked" 상태로 명시
- 문제점을 "리스크" 섹션에 기록
- 연관 항목으로 연결

### 문제점 추적의 중요성
- "이전 회의 액션 상태 확인" 섹션이 Raw에 있어야 함
- 또는 Wiki의 각 항목이 "상태 변화" 섹션으로 추적해야 함
- 현재 구조로는 이미 충분함

## 📚 Wiki 활용 권장사항

### 매 회의마다
1. Raw 회의록 기록
2. 새로운 D/A/P에 ID 부여 및 Wiki 파일 생성
3. 기존 D/A/P의 상태 업데이트

### 주간 단위
- 모든 진행 중인 A (action)의 상태 확인
- "at_risk" 항목 점검
- "blocked" 항목의 블로킹 원인 해결 검토

### 월간 단위
- 완료된 항목들 review
- P (pending)이 너무 많으면 의사결정 구조 점검
- "untracked" 항목이 있으면 추적 체계 개선
