# Wiki 스키마 정의

**작성일**: 2026-08-10  
**버전**: 1.0  
**목적**: Wiki 계층(결정, 액션, 보류, 뷰)의 표준 구조 정의

---

## 📋 개요

Raw 회의록은 원본으로 순수하게 유지하고, Wiki 계층에서 다음을 관리:
- **원자 레코드**: 결정(D-xxx), 액션(A-xxx), 보류(P-xxx)
- **뷰**: 회의별, 사람별, 주제별 조합

---

## 1. 결정 (Decision) - D-xxx.md

### 파일명 규칙
```
wiki/결정/D-{number}.md
예: D-001.md, D-002.md, D-003.md
```

### Front Matter 필드

| 필드 | 필수 | 형식 | 설명 |
|------|------|------|------|
| `id` | ✅ | D-001 | 고유 ID (숫자 순증가) |
| `source` | ✅ | 파일 경로 | raw/YYYY-MM-DD-회의명.md (여러 개면 → 로 연결) |
| `title` | ✅ | 텍스트 | 의사결정의 간단한 설명 |
| `owner` | ✅ | 이름 | 담당자 또는 의사결정자 |
| `status` | ✅ | 상태 | open / closed / pending / unclear / at_risk |
| `created_date` | ✅ | YYYY-MM-DD | 의사결정된 날짜 |
| `last_modified` | ❌ | YYYY-MM-DD | 마지막 수정 날짜 |

### Status 정의

| 상태 | 이모지 | 의미 | 예시 |
|------|--------|------|------|
| **open** | 🔄 | 진행 중 | 결정했으나 아직 실행 중 |
| **closed** | ✅ | 완료 | 결정이 완전히 구현됨 |
| **pending** | ⏳ | 대기 | 선행 조건 대기 |
| **unclear** | ❓ | 상태 불명 | 진행 여부 불명확 |
| **at_risk** | 🔴 | 위험 | 기한 또는 조건 위험 |

### 필수 섹션

```markdown
## 내용
의사결정의 핵심 1-2문장.

## 배경
왜 이 결정이 필요했는가?

## 의사결정 세부사항
- 의사결정자: 
- 근거: 
- 날짜:

## 현재 상태
- 진행 여부
- 마지막 업데이트

## 연관 항목
- [[A-001]]: ...
- [[D-002]]: ...
```

### 선택 섹션 (권장)

```markdown
## 선행 조건
이것이 실행되기 위해 필요한 것들

## 리스크 또는 미흡
- 검토되지 않은 항목
- 영향도 평가 미흡

## 상태 변화
- 2026-04-16: 결정됨
- 2026-05-14: 연기됨 (사유: ...)

## 영향도
누가, 무엇이 영향을 받는가?
```

## 2. 액션 아이템 (Action) - A-xxx.md

### 파일명 규칙
```
wiki/액션아이템/A-{number}.md
예: A-001.md, A-002.md, A-003.md
```

### Front Matter 필드

| 필드 | 필수 | 형식 | 설명 |
|------|------|------|------|
| `id` | ✅ | A-001 | 고유 ID |
| `source` | ✅ | 파일 경로 | raw/YYYY-MM-DD-회의명.md |
| `title` | ✅ | 텍스트 | 할일의 간단한 설명 |
| `owner` | ✅ | 이름 | 담당자 |
| `status` | ✅ | 상태 | open / in_progress / completed / blocked / untracked |
| `created_date` | ✅ | YYYY-MM-DD | 할당된 날짜 |
| `due_date` | ✅ | YYYY-MM-DD | 기한 |
| `completed_date` | ❌ | YYYY-MM-DD | 완료한 날짜 (완료 시에만) |

### Status 정의

| 상태 | 이모지 | 의미 | 예시 |
|------|--------|------|------|
| **open** | 📭 | 아직 미시작 | 할당됨, 대기 중 |
| **in_progress** | 🔄 | 진행 중 | 현재 작업 중 |
| **completed** | ✅ | 완료됨 | 작업 끝남 |
| **blocked** | ⏸️ | 블로킹 | 다른 작업에 의해 진행 불가 |
| **untracked** | ❌ | 미추적 | 진행 상황이 기록되지 않음 |

### 필수 섹션

```markdown
## 액션 내용
구체적으로 무엇을 해야 하는가?

## 기한
- 할당일: YYYY-MM-DD
- 기한: YYYY-MM-DD
- 상태: 진행 여부 (진행 중 / 완료 / 미완료)

## 진행 상황
- 마지막 업데이트: 날짜
- 진행률: X%

## 영향도
이것이 영향을 미치는 것들 (D-xxx, 기한 등)

## 연관 항목
- [[D-003]]: ...
- [[A-001]]: ...
```

### 선택 섹션 (권장)

```markdown
## 배경
왜 이 액션이 필요한가?

## 리스크
- 시간 압박
- 선행 조건 미충족
- 문서 품질 우려

## 선행 조건
이 액션을 진행하기 위해 필요한 것들

## 상태 변화
- 2026-04-16: 할당됨
- 2026-05-14: 진행 상황 미보고 (위험)
```

## 3. 보류/질문 (Pending) - P-xxx.md

### 파일명 규칙
```
wiki/보류/P-{number}.md
예: P-001.md, P-002.md
```

### Front Matter 필드

| 필드 | 필수 | 형식 | 설명 |
|------|------|------|------|
| `id` | ✅ | P-001 | 고유 ID |
| `source` | ✅ | 파일 경로 | raw/YYYY-MM-DD-회의명.md |
| `title` | ✅ | 텍스트 | 미해결 사항 설명 |
| `owner` | ✅ | unassigned 또는 이름 | 담당자 (미정이면 unassigned) |
| `status` | ✅ | 상태 | pending / stalled / escalated |
| `created_date` | ✅ | YYYY-MM-DD | 기록된 날짜 |

### Status 정의

| 상태 | 의미 |
|------|------|
| **pending** | 진행 대기 중 (리소스 부족, 우선순위 낮음) |
| **stalled** | 진행 안 됨 (담당자 미정, 의견 불일치) |
| **escalated** | 상위 관리자에게 보고됨 |

### 필수 섹션

```markdown
## 문제 설명
무엇이 미해결되었는가?

## 배경
왜 보류되었는가?

## 현재 상태
- 담당자: 미정 / 이름
- 기한: 미정 / YYYY-MM-DD
- 진행도: 0%

## 영향도
이것이 해결되지 않을 경우:
- D-001 구현 불가
- 고객사 공지 불가

## 개선 필요
- [ ] 담당자 할당
- [ ] 기한 설정
- [ ] 액션으로 격상
```

## 4. 뷰 (View)

### 4.1 회의 뷰 - wiki/회의/YYYY-MM-DD-회의명.md

**목적**: 특정 회의의 모든 D/A/P를 한눈에 보기

**주요 섹션**:
- 개요 (날짜, 참석자, 안건 수)
- 주요 의사결정 (D-xxx 목록)
- 액션 아이템 (A-xxx 목록)
- 보류 사항 (P-xxx 목록)
- 위험도 대시보드 (상태/위험도 표)
- 연관도 (의존 관계 다이어그램)

### 4.2 사람 뷰 - wiki/사람/{이름}.md

**목적**: 특정 인물이 Owner인 모든 항목

**주요 섹션**:
- 담당 의사결정 (D-xxx 목록)
- 담당 액션 (A-xxx 목록)
- 보류 중인 것 (P-xxx 목록)
- 상태 요약 (진행 상황 한눈에)

### 4.3 주제 뷰 - wiki/주제/{주제명}.md

**목적**: 특정 주제의 모든 관련 항목

**주요 섹션**:
- 관련 의사결정 (D-xxx)
- 관련 액션 (A-xxx)
- 현재 상태
- 타임라인

## 5. 공통 필드 규칙

### ID 체계
```
D-001, D-002, D-003, ...  (같은 타입 내에서 순증가)
A-001, A-002, A-003, ...
P-001, P-002, P-003, ...

규칙:
- 같은 타입 내에서만 순증가
- 한번 할당되면 변경되지 않음 (재사용 금지)
- 새로운 항목이 생기면 마지막 번호에 +1
```

### Source 필드
```
단일 출처:
source: raw/2026-04-16-제품주간회의.md

다중 출처 (여러 회의에서 나온 항목):
source: raw/2026-04-16-제품주간회의.md → raw/2026-05-14-제품주간회의.md

다중 출처 (3개 이상):
source: raw/2026-04-16-제품주간회의.md, raw/2026-05-14-제품주간회의.md, ...
```

### 날짜 형식
```
ISO 8601 표준: YYYY-MM-DD
예: 2026-05-14, 2026-08-10
```

### 사람 이름
```
한글 이름 또는 이름(역할)
예: 
- 이지혜(PM)
- 박준서(개발)
- 최민아
- unassigned (담당자 미정)
```

### 상태 이모지

```markdown
완료/성공 관련
✅ completed / closed
✔️ done
⭐ success

진행 중
🔄 in_progress
⏳ pending
⏸️ blocked / on_hold
🚀 launched

문제/위험
❌ failed / untracked / stalled
🔴 critical / at_risk
🟡 warning
⚠️ caution

불명확
❓ unclear
🤷 unknown
```

### 연관 항목 링크
```markdown
같은 Wiki 항목 내에서:
- [[D-001]]: 다른 파일 참조
- [[A-003]]: 
- [[P-001]]: 

같은 문서 내 제목 참조:
- **D-002**: 앞서 정의한 섹션으로

설명과 함께:
- **[[A-003]]**: A사 스펙 확보 (선행 조건)
```

## 6. 변환 규칙: Raw → Wiki

### Raw에서 발견하는 패턴 → Wiki 항목

#### 의사결정 (Decision) 생성 기준

Raw 회의록에서 다음을 찾으면 **D-xxx** 생성:

```markdown
명시적 결정:
## 결정
- **내용** | Owner: 이름

또는

### 결정
- 내용 (명시적으로 "결정했다"고 표현)

또는 (자유 형식에서도)
이지혜: 그럼 A사로 가자 → 결정됨
```

**판단 기준**:
- 누군가가 "~하자" / "~로 결정했다" / "~로 가자"고 명시적으로 말함
- 리더가 "아, 이건 결정이 된 거다"라고 인지할 수 있을 정도

#### 액션 아이템 (Action) 생성 기준

Raw 회의록에서 다음을 찾으면 **A-xxx** 생성:

```markdown
## 액션 아이템
- [ ] 이름 — 할일 설명 (~마감일)

또는 (자유 형식에서도)
박준서: 내가 비교표 만들어서 다음 회의에 가져올게 → 액션

또는 (회의 중간에 나온 말)
이지혜: 강태우가 계약 조건 확인해봐야 할 것 같은데
```

**판단 기준**:
- 명확한 담당자와 할일이 있음
- 기한이 있거나 "다음 회의까지" 같은 암묵적 기한이 있음
- 완료 여부를 판단할 수 있을 정도의 구체성

#### 보류/질문 (Pending) 생성 기준

Raw 회의록에서 다음을 찾으면 **P-xxx** 생성:

```markdown
## 기타
- 담당자 미정 사항
- 미해결 질문
- 후속 필요 사항
```

**판단 기준**:
- 결정도 아니고 액션도 아닌 것
- 담당자가 미정이거나 기한이 없음
- 미래에 다시 논의해야 할 것 같음

## 7. 체크리스트: Wiki 항목 작성 시

- [ ] ID 중복 확인 (같은 타입 내에서)
- [ ] Source 명시 (어느 Raw 파일에서 왔는지)
- [ ] Title이 명확한가? (2-3줄 이상 필요 없음)
- [ ] Owner가 명시되어 있는가?
- [ ] Status가 현재 상태를 반영하는가?
- [ ] 필수 섹션이 모두 있는가?
  - [ ] 내용/배경
  - [ ] 현재 상태 또는 진행 상황
  - [ ] 연관 항목
- [ ] 리스크/미흡한 부분이 명시되어 있는가?
- [ ] 날짜가 YYYY-MM-DD 형식인가?
- [ ] 이모지로 상태가 시각화되어 있는가?
- [ ] 연관 항목이 올바르게 링크되어 있는가?

## 8. 활용 지침

### 매 회의마다
1. Raw 회의록 기록
2. 새로운 D/A/P 추출 및 ID 부여
3. Wiki 파일 생성
4. 기존 D/A/P 상태 업데이트 (상태 변화 섹션 추가)

### 주간 단위
- 진행 중인 A (action)의 상태 확인
- "at_risk" 항목 점검
- "blocked" 항목의 원인 해결 검토

### 월간 단위
- 완료된 항목들 review
- P (pending)이 너무 많으면 의사결정 구조 점검
- "untracked" 항목의 추적 시작
