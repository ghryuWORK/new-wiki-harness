# 6. 저장소 구조

## 전체 구조도

```
meetings-ssot/
│
├── CLAUDE.md                          # 운영 원칙 및 규칙 (Schema Layer)
├── README.md                          # 팀용 빠른 시작 가이드
│
├── 📁 raw/                            # ========== RAW LAYER (SSOT) ==========
│   ├── 2026-08-10-sync.md
│   ├── 2026-08-03-sync.md
│   └── ...
│
└── 📁 wiki/                           # ========== WIKI LAYER (파생물) ==========
    │                                  # 주의: 통째로 삭제 가능 (Raw에서 재생성 가능)
    │
    ├── 📁 결정/                       # 액션 레코드 (원자 단위, 1파일 1건)
    │   ├── D-001.md
    │   ├── D-002.md
    │   └── ...
    │
    ├── 📁 보류/                       # 액션 레코드 (미해결 오픈 이슈)
    │   ├── P-001.md
    │   └── ...
    │
    ├── 📁 액션아이템/                 # 액션 레코드 (할당된 작업)
    │   ├── A-001.md
    │   ├── A-002.md
    │   └── ...
    │
    ├── 📁 회의/                       # 뷰 (Raw에서 조립한 회의별 요약)
    │   ├── 2026-08-10-sync.md
    │   └── ...
    │
    ├── 📁 사람/                       # 뷰 (특정 사람의 관여 항목 모음)
    │   ├── alice.md
    │   ├── bob.md
    │   └── ...
    │
    └── 📁 주제/                       # 뷰 (특정 주제의 모든 항목)
        ├── infra.md
        ├── hiring.md
        └── ...
```

## 계층별 설명

### Raw Layer (`raw/`)
**역할**: SSOT (Single Source of Truth)

- **소유권**: 팀 전체
- **포함**: 원본 회의록 파일만
- **파일명**: `YYYY-MM-DD-{meeting-name}.md`
- **삭제 가능성**: ❌ 불가 (영구 보관)
- **변경**: Git history로 모든 변경사항 추적
- **접근**: 높은 빈도 (회의 후 즉시 업데이트, 자주 참조)

### Wiki Layer (`wiki/`)
**역할**: Derived Data (파생 데이터)

**특징**: 통째로 삭제 가능 (Raw에서 재생성 가능)

#### 원자 레코드 (1파일 1건)
- **결정/**: Decision 중앙 레지스트리 (D-001, D-002, ...)
- **액션아이템/**: Action Item 중앙 레지스트리 (A-001, A-002, ...)
- **보류/**: Open Question 레지스트리 (P-001, P-002, ...)

각 파일 포함 내용:
```yaml
---
id: D-001 | A-001 | P-001
source: raw/2026-08-10-제품주간회의.md
owner: 이름
status: open | closed | pending | resolved
created_date: 2026-08-10
---

## 내용
Raw 회의록에서 추출한 해당 항목의 상세 내용
```

#### 뷰 (레코드에서 조립)
- **회의/**: 각 회의의 전체 요약 (결정/액션/보류 포함)
- **사람/**: 특정 사람(alice, bob 등)이 관여한 모든 항목
- **주제/**: 특정 주제(infra, hiring 등)의 모든 관련 항목

각 뷰는 자동 또는 수동으로 생성되며, 원자 레코드 파일들의 링크로 구성

## 파일 이름 규칙

### Raw Layer
```
raw/YYYY-MM-DD-{회의명}.md
예: raw/2026-04-16-제품주간회의.md
    raw/2026-06-25-온보딩개선회의.md
```
- 한글 회의명 사용 가능
- 형식: 날짜-회의명 (하이픈으로 구분)

### Wiki Layer - 원자 레코드
```
wiki/결정/D-{number}.md         → D-001, D-002, ...
wiki/액션아이템/A-{number}.md   → A-001, A-002, ...
wiki/보류/P-{number}.md          → P-001, P-002, ...
```

### Wiki Layer - 뷰
```
wiki/회의/{YYYY-MM-DD}-{name}.md
wiki/사람/{name}.md
wiki/주제/{topic}.md
```

## 접근 패턴

### 일반 팀 멤버
1. `raw/` 에서 최신 회의록 확인
2. `wiki/회의/` 에서 회의 요약 조회
3. `wiki/{사람|주제}/` 에서 자신의 관여 항목 검색

### SSOT Maintainer
1. `raw/` 에서 회의록 관리 (수정/정정)
2. Git history로 변경사항 추적
3. `wiki/` 의 동기화 상태 확인

### Meeting Organizer
1. `raw/` 에서 미해결 항목 확인
2. `wiki/` 의 다양한 뷰에서 Agenda 후보 수집
3. 새로운 Agenda 문서 생성

## 동기화 규칙

- Raw 회의록 수정 → Wiki 파생물도 업데이트 (24시간 내)
- Wiki 파일이 outdated → Raw 기준으로 재동기화
- 충돌 발생 → 항상 Raw 기준으로 판단 및 수정
