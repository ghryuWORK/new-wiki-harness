# Wiki 스키마 정의

Wiki 계층의 모든 항목(결정, 액션, 보류, 뷰)이 따를 구조와 필드를 정의합니다.

---

## 1. 결정 (Decision) - D-xxx.md

### 목적
Raw 회의록에서 추출한 의사결정 사항을 중앙 레지스트리로 관리.

### 파일명
```
wiki/결정/D-{number}.md
예: D-001.md, D-002.md
```

### Front Matter (필수)
```yaml
---
id: D-001
source: raw/YYYY-MM-DD-회의명.md
title: "의사결정 제목"
owner: 담당자명
status: open | closed | pending | unclear | at_risk
created_date: YYYY-MM-DD
last_modified: YYYY-MM-DD
---
```

#### 필드 설명

| 필드 | 필수 | 형식 | 설명 |
|------|------|------|------|
| `id` | ✅ | D-001 | 고유 ID (숫자로 순증가) |
| `source` | ✅ | 파일 경로 | Raw 회의록 출처 (여러 개 가능: `→`로 구분) |
| `title` | ✅ | 텍스트 | 의사결정의 간단한 설명 |
| `owner` | ✅ | 이름 | 담당자 또는 의사결정자 |
| `status` | ✅ | 상태 | 현재 상태 (아래 상태 정의 참조) |
| `created_date` | ✅ | YYYY-MM-DD | 의사결정된 날짜 |
| `last_modified` | ❌ | YYYY-MM-DD | 마지막 수정 날짜 |

#### Status 종류

| 상태 | 의미 | 예시 |
|------|------|------|
| **open** | 진행 중 | 결정했으나 아직 진행/구현 중 |
| **closed** | 완료됨 | 결정 사항이 완전히 구현됨 |
| **pending** | 대기 중 | 선행 조건 대기 |
| **pending_implementation** | 구현 대기 | 의사결정은 됐으나 아직 시작 안 함 |
| **in_progress** | 진행/논의 중 | 분석, 논의, 검토 진행 중 |
| **unclear** | 상태 불명 | 진행 여부 불명확 |
| **at_risk** | 위험 | 기한 또는 조건 위험 상태 |

### 본문 구조

**필수 섹션**:
- 내용/의사결정
- 배경
- 의사결정 세부사항
- 현재 상태

**다중 회의 항목인 경우 필수**:
- 상태 변화 (2026-04-16 → 2026-05-14 등)

**선택 섹션**

```markdown
## 내용 또는 의사결정
의사결정의 핵심 내용 1-2문장.

## 배경
왜 이 결정이 필요했는가? 어떤 상황에서?

## 의사결정 과정
(선택) 다단계 결정인 경우
### 1단계 (날짜): ...
### 2단계 (날짜): ...

## 의사결정 세부사항
- 결정자: 누가 결정했는가?
- 근거: 어떤 데이터/논리를 기반으로?
- 영향도: 어느 범위에 영향?

## 현재 상태
- 구현 여부
- 진행률
- 마지막 업데이트

## 선행 조건
이 결정이 실행되기 위한 선행 조건들
- A-003: 스펙 문서 확보 필수
- P-001: 정산 프로세스 확인 필요

## 리스크 또는 미흡 사항
- 검토되지 않은 항목
- 영향도 평가 미흡
- 구현 불확실성

## 영향도
### 긍정적
- ...

### 부정적 또는 위험
- ...

## 연관 항목
- **D-002**: PG사 선정 (관련)
- **A-003**: 스펙 확보 (선행)
- **P-001**: 정산 프로세스 (의존)

## 개선 필요 또는 다음 단계
- [ ] 구체적인 실행 계획 수립
- [ ] 리스크 대응 방안 검토
- [ ] 기한 설정
```

## 2. 액션 아이템 (Action) - A-xxx.md

### 목적
Raw 회의록에서 추출한 할당된 작업을 중앙 레지스트리로 관리.

### 파일명
```
wiki/액션아이템/A-{number}.md
예: A-001.md, A-002.md
```

### Front Matter (필수)
```yaml
---
id: A-001
source: raw/YYYY-MM-DD-회의명.md
title: "액션 아이템 제목"
owner: 담당자명
status: open | in_progress | completed | blocked | untracked
created_date: YYYY-MM-DD
due_date: YYYY-MM-DD
completed_date: YYYY-MM-DD
---
```

#### 필드 설명

| 필드 | 필수 | 형식 | 설명 |
|------|------|------|------|
| `id` | ✅ | A-001 | 고유 ID |
| `source` | ✅ | 파일 경로 | Raw 회의록 출처 |
| `title` | ✅ | 텍스트 | 할일의 간단한 설명 |
| `owner` | ✅ | 이름 | 담당자 |
| `status` | ✅ | 상태 | 현재 상태 |
| `created_date` | ✅ | YYYY-MM-DD | 할당된 날짜 |
| `due_date` | ✅ | YYYY-MM-DD | 기한 |
| `completed_date` | ❌ | YYYY-MM-DD | 완료한 날짜 |

#### Status 종류

| 상태 | 의미 | 예시 |
|------|------|------|
| **open** | 아직 시작 안 함 | 할당됨, 대기 중 |
| **in_progress** | 진행 중 | 현재 작업 중 |
| **completed** | 완료됨 | 작업 끝남 |
| **blocked** | 블로킹됨 | 다른 작업에 의해 진행 불가 |
| **on_hold** | 홀드됨 | 의도적 일시 중단 (재개 시점 명시) |
| **at_risk** | 위험 | 기한 임박, 완료 불확실 |
| **untracked** | 미추적 | 진행 상황이 기록되지 않음 |

### 본문 구조

```markdown
## 액션 내용
구체적으로 무엇을 해야 하는가?

## 배경
왜 이 액션이 필요한가? 어떤 맥락에서?

## 기한
- 할당일: YYYY-MM-DD
- 기한: YYYY-MM-DD
- 지연 기간: X일 (기한 경과한 경우)

## 진행 상황
### 상태
- 시작: 아직 안 함 / 진행 중 / 완료
- 진행률: X%
- 마지막 업데이트: 날짜

### 완료 여부
- ✅ 완료 (완료일: YYYY-MM-DD)
- 🔄 진행 중 (예상 완료: YYYY-MM-DD)
- ❌ 미완료 또는 미추적
- ⏸️ 블로킹 중 (사유: ...)

## 리스크 또는 우려 사항
- 시간 압박
- 문서 품질 우려
- 리소스 부족
- 선행 조건 미충족

## 선행 조건
이 액션을 진행하기 위해 필요한 것들
- D-002: PG사 선정 (완료됨)
- A-001: 비교표 (완료됨)
- A-003: 스펙 문서 (진행 중)

## 영향도
이 액션의 결과가 무엇에 영향을 미치는가?
- D-003: 결제 연동 일정에 의존
- 엔터프라이즈 고객 3곳 계약
- Q3 계획 (A-004와 충돌)

## 연관 항목
- **D-002**: PG사 선정 (선행)
- **D-003**: 결제 연동 (의존)
- **A-002**: 계약 조건 (병렬)

## 모니터링 필요 여부
(우선순위가 높거나 위험한 경우)
- 주 1회
- 주 2-3회
- 일일
- 필요시

## 상태 변화
(다중 회의에 걸친 항목인 경우)
- 2026-04-16: 할당됨
- 2026-05-14: 진행 상황 미보고 (기한 경과)

## 리소스/의존성
(리소스 충돌이 있는 경우)
- 담당자: 최민아
- 병렬 진행 불가: A-004와 리소스 충돌
- 영향: A-004가 대기 중 (복귀 예정: 2026-05-28)
```

## 3. 보류/질문 (Pending) - P-xxx.md

### 목적
미해결 사항, 열린 질문, 담당자 미정인 과제들을 추적.

### 파일명
```
wiki/보류/P-{number}.md
예: P-001.md, P-002.md
```

### Front Matter (필수)
```yaml
---
id: P-001
source: raw/YYYY-MM-DD-회의명.md
title: "보류/질문 제목"
owner: unassigned | 담당자명
status: pending | stalled | escalated
created_date: YYYY-MM-DD
---
```

#### Status 종류

| 상태 | 의미 |
|------|------|
| **pending** | 진행 대기 중 (리소스 부족 등) |
| **stalled** | 진행 안 됨 (담당자 미정 등) |
| **escalated** | 상위 관리자에게 보고됨 |

### 본문 구조

```markdown
## 문제 설명
무엇이 미해결되었는가?

## 배경
왜 이것이 보류되었는가?

## 현재 상태
- 담당자: unassigned
- 기한: 미정
- 진행도: 0%

## 원인 분석
왜 진행되지 않았는가?
- 담당자 미정
- 우선순위 밀림
- 선행 조건 미충족

## 영향도
이것이 해결되지 않을 경우:
- D-001 구현 불가
- 고객사 공식 공지 불가

## 관련 의사결정 또는 액션
- D-001: 정산 주기 월 1회 (구현 막힘)
- A-006 (할당 필요): 정산 프로세스 확인

## 개선 필요
- [ ] 담당자 할당
- [ ] 기한 설정
- [ ] 우선순위 결정
- [ ] 액션으로 격상
```

## 4. 뷰 (View)

### 4.1 회의 뷰 - wiki/회의/YYYY-MM-DD-회의명.md

**목적**: 특정 회의의 모든 결정, 액션, 보류를 한눈에 보기.

**구조**:
```markdown
# YYYY-MM-DD 회의명

## 개요
- 날짜, 참석자, 안건 개수

## 주요 의사결정
각 결정(D-xxx)으로의 링크 + 요약

## 액션 아이템
각 액션(A-xxx)으로의 링크 + 상태

## 보류/미해결
각 보류(P-xxx)로의 링크

## 위험도 대시보드
| ID | 제목 | 상태 | 위험도 |
| ... |

## 연관도
흐름도 또는 관계도
```

### 4.2 사람 뷰 - wiki/사람/{이름}.md

**목적**: 특정 인물이 Owner인 모든 항목 모으기.

**구조**:
```markdown
# {이름}

## 담당 의사결정
- D-001: ...
- D-002: ...

## 담당 액션
- A-001: ...
- A-003: ...

## 보류 중인 것
- P-001: ...

## 상태 요약
```

### 4.3 주제 뷰 - wiki/주제/{주제명}.md

**목적**: 특정 주제(기능, 영역)에 관한 모든 항목 모으기.

**구조**:
```markdown
# {주제명}

## 관련 의사결정
- D-002: PG사 선정
- D-003: 결제 연동 일정

## 관련 액션
- A-001: 비교표
- A-003: 스펙 확보

## 현재 상태
- 진행률: X%
- 주요 리스크: ...

## 타임라인
- 2026-04-16: 결정 수립
- 2026-05-14: 일정 조정
```

## 5. 필드 규칙

### 공통 규칙

#### ID 체계
```
D-001, D-002, ... (의사결정)
A-001, A-002, ... (액션)
P-001, P-002, ... (보류)
```
- 같은 타입 내에서 순증가 숫자
- 변경되지 않음 (재사용 금지)

#### Source 필드
```
source: raw/2026-04-16-제품주간회의.md                    # 단일 출처
source: raw/2026-04-16-제품주간회의.md → raw/2026-05-14-제품주간회의.md  # 다중 출처
```

#### Status 이모지
```
✅ completed / closed
🔄 in_progress
⏸️ blocked / on_hold
❌ untracked / stalled
🟡 at_risk
🔴 critical
❓ unclear
```

#### 날짜 형식
```
YYYY-MM-DD (ISO 8601)
예: 2026-05-14
```

#### 사람 이름
```
한글 이름(역할)
예: 이지혜(PM), 박준서(개발)
또는 역할 없이: 강태우
```

#### 연관 항목 링크
```markdown
- [[D-001]]: 다른 항목 참조 (같은 폴더에서)
- [[A-003]]: 
- **D-002**: 같은 문서 내 제목으로 참조
```

## 6. 변환 규칙: Raw → Wiki

### Raw 회의록에서 Wiki로 추출하는 방법

#### 의사결정 (Decision) 추출
Raw 회의록에서 다음을 찾으면 **D-xxx** 생성:
```markdown
## 결정
- **내용** | Owner: 이름 | Due: 2026-08-15

또는 

### 결정
- 내용 (명시적으로 결정했다고 표현)
```

#### 액션 아이템 (Action) 추출
Raw 회의록에서 다음을 찾으면 **A-xxx** 생성:
```markdown
## 액션 아이템
- [ ] 이름 — 할일 설명 (~마감일)
```

#### 보류/질문 (Pending) 추출
Raw 회의록에서 다음을 찾으면 **P-xxx** 생성:
```markdown
## 기타
- 담당자 미정 사항
- 미해결 질문
- 후속 필요한 것
```

## 8. 체크리스트: Wiki 항목 작성 시

- [ ] ID 확인 (중복 없는지)
- [ ] Source 명시 (어느 Raw 파일에서 왔는지)
- [ ] Title이 명확한가
- [ ] Owner가 명시되어 있는가
- [ ] Status가 현재 상태를 반영하는가 (new: pending_implementation, in_progress, on_hold, at_risk 추가)
- [ ] 필수 섹션이 있는가 (내용, 배경, 현재 상태)
- [ ] 리스크/미흡한 부분이 명시되어 있는가
- [ ] 연관 항목(D/A/P)이 링크되어 있는가
